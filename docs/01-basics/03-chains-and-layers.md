# 03. 公链、Layer 1、Layer 2

## 一句话理解

公链是**不同的「区块链网络」**，Layer 1 是「地基」，Layer 2 是「在地基上加盖的快速通道」。

## 为什么会有这么多链

如果区块链只有一条，那一切好办。但现实是——比特币、以太坊、Solana、BNB Chain、Polygon、Arbitrum、Base⋯⋯名字一大堆，而且每年还在冒新的。

为什么？因为区块链有一个绕不开的天花板，叫「**不可能三角**」：

> **去中心化、安全、性能——三个最多只能挑两个。**

- 想又安全又去中心化（节点多、谁都能参与）→ 性能就上不去（比特币、早期以太坊）
- 想又快又去中心化 → 安全性就难保证
- 想又快又安全 → 就得牺牲去中心化（节点少、参与门槛高，比如某些高性能链）

每条链对这三角的取舍不同，所以才会冒出这么多链，每条都说自己是「最优解」。其实没有最优，**只有取舍**。

## 公链 vs 联盟链 vs 私链

先把这个分类讲清楚，后面就不再混淆了。

| 类型 | 谁能参与 | 谁能记账 | 典型场景 |
|---|---|---|---|
| **公链** | 任何人 | 任何人 | 比特币、以太坊——我们这本书讲的几乎都是公链 |
| **联盟链** | 准入制 | 联盟内成员 | 几家银行联合搭一个跨行清算系统 |
| **私链** | 一个机构内部 | 这个机构 | 公司内部的审计系统 |

「真正 Web3」的部分基本都在**公链**上。联盟链和私链虽然也叫区块链，但它们本质上更像「一群已经互相信任的人共同维护的数据库」，跟 Web3 那种「谁都不用信任」的精神不太一样。

下面说的「链」，默认都指公链。

## Layer 1：地基

**Layer 1（L1）= 一条独立的、自己有共识机制的区块链**。

它自己处理交易、自己出块、自己有一套记账员。可以理解为「主网」「底层公链」。

常见的 L1：

| 链 | 一句话定位 |
|---|---|
| **比特币（Bitcoin）** | 最早的链，定位是「数字黄金」，只做价值存储和转账，不跑复杂应用 |
| **以太坊（Ethereum）** | 第一个大规模跑通「通用智能合约」的链，DeFi、NFT 几乎都从这里开始，但 L1 慢且贵 |
| **Solana** | 主打高速度低费用，单链做高性能，节点门槛比以太坊高 |
| **BNB Chain** | 币安生态影响力很大的链，便宜、快，但验证者和治理更集中，去中心化程度有争议 |
| **Tron** | 稳定币转账用得多，尤其是 USDT |

你不需要记全。重点是：**它们都是 L1，互相独立，互不通账**。比特币上的 BTC 不会自动出现在以太坊上，反过来也一样。

## Layer 2：地基上的快速通道

以太坊安全又去中心化，代价是慢且贵——网络一拥堵，转一笔账可能要等几分钟、付几十美元。这显然没法日常用。

**Layer 2（L2）= 在 L1 之上加盖的一层，把交易先在 L2 上处理掉，再把结果「打包结算」回 L1**。

用一个类比：

> L1 像**法院**——慢、贵、但判决最终有效。  
> L2 像**社区调解委员会**——快、便宜，把日常小纠纷在社区内部解决掉，只有最终结果上报法院备案。

你在 L2 上发起 100 笔交易，L2 把这 100 笔在自己内部处理完，最后只往 L1 上写一条「这 100 笔的最终结果是 XX」。L1 只需要验证这一条，省下了大量工作。

L2 的好处：
- **快**：几秒确认，不用等 L1
- **便宜**：费用通常是 L1 的几十分之一甚至几百分之一
- **安全**：成熟 Rollup 会把数据或证明提交到 L1，最终安全性很大程度上靠 L1 兜底

但也别把「L2 靠 L1」理解成「所有 L2 都和 L1 一样安全」。L2 还会有自己的风险：排序器可能短暂宕机或审查交易，跨链桥合约可能出问题，某些 L2 还保留升级管理员权限。越新的 L2，越要把它当成「还在变成熟的基础设施」。

代表的 L2（基本都建在以太坊之上）：

| L2 | 特点 |
|---|---|
| **Arbitrum** | 用得最多的以太坊 L2 之一 |
| **Optimism** | 同上，另一个主力 |
| **Base** | Coinbase 推的 L2，对新手友好 |
| **zkSync / Scroll / Linea** | 用「零知识证明」技术的 L2，更前沿一些 |

你不需要一开始就分清楚所有技术差别。先记住：**L2 = L1 的扩容方案，便宜快，但安全模型要看它具体怎么把数据、证明和退出机制放回 L1**。

## 多链世界，钱怎么搬

链之间互相独立，那 A 链上的资产怎么搬到 B 链上？答案是：**跨链桥（Bridge）**。

跨链桥的原理大致是：

> 你在 A 链上把 100 USDT 锁进一个合约 → 桥在 B 链上给你发 100 张「等值凭证」 → 你拿着凭证在 B 链上用 → 想回 A 链就反过来一遍。

听上去合理，但跨链桥是 Web3 里**被黑得最惨的环节**——历史上几次单次损失上亿美元的事件，大多发生在跨链桥。原因是桥要管的资产规模大、攻击面广。

实操建议（这本书不给投资建议，但安全提醒还是要给）：

- **能不跨链就不跨链**，能用 L1/L2 原生的就用原生的
- **必须跨链时，用官方桥**，不要用看起来便宜但来路不明的小桥
- **大额分批跨**，别一次梭哈

## 怎么记这一章

| 概念 | 一句话 |
|---|---|
| 公链 | 任何人都能用、都能参与记账的区块链 |
| L1 | 独立的底层链，自己有共识，自己结算 |
| L2 | 建在 L1 之上的快速通道，便宜快，安全模型取决于它如何依赖 L1 |
| 跨链桥 | 在不同链之间搬资产的设施，方便但风险高 |
